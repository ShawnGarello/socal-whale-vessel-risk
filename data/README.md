# Local data root

**Owns:** how source data is stored on a local machine during this project.

Nothing in this directory except this file and the `.gitkeep` placeholders is
committed. The ignore rules that enforce that live in the repository-root
[`.gitignore`](../.gitignore).

This directory is a **local working area, not a distribution channel.** A clone
of this repository does not come with the data. It comes with the instructions
for obtaining the data, which are in [`../docs/data-sources.md`](../docs/data-sources.md).

---

## Layout

```
data/
├── raw/        untouched source downloads, exactly as retrieved
├── interim/    intermediate processing outputs
└── derived/    validated outputs intended for publication
```

### `raw/`

Files as they arrived from the publisher, byte-for-byte. **Never edited, never
renamed, never cleaned in place.** If a raw file needs to change, that means the
processing path needs to change instead — the raw copy is the fixed starting
point that makes a rerun meaningful.

Each retrieval gets its own subdirectory named for the source. Provenance for
every retrieval is recorded in
[`../docs/data-sources.md`](../docs/data-sources.md) — that is the committed,
authoritative record. A local `README.md` may also sit beside a download as a
convenience copy; `README.md` is the one filename inside `data/` that is not
ignored, so use it rather than `notes.txt` if you want the note under version
control. Either way, what gets recorded is:

- the exact source URL or service endpoint,
- the retrieval method and every parameter used (bounding box, dates, filters),
- the retrieval date,
- any stated dataset version or model vintage,
- the file sizes and checksums as retrieved.

Provenance cannot be reconstructed after the fact. It is recorded at the moment
of retrieval or it is lost.

### `interim/`

Anything produced on the way from raw to derived: reprojected inputs, clipped
extracts, cleaned record sets, gridded intermediates. Freely deletable. If
deleting everything here breaks the ability to reproduce a result, then a step
exists only as a file and not as a process, which is a defect in the process.

### `derived/`

Validated outputs that are ready to publish or to summarize from. These are
generated by the processing path, not hand-edited. They are published to ArcGIS
Online rather than committed, with the single exception noted in
[`../docs/development.md`](../docs/development.md): small results the
application reads, such as a summary-statistics file, may be committed so the
application and its numbers stay versioned together. Such a file is committed by
explicit path, against the default ignore, and records what produced it and when.

---

## Rules

1. **Nothing here is committed** unless it is documentation or an explicitly
   re-included small result. The default is ignore; inclusion is deliberate and
   per-path.
2. **Never commit credentials, API keys, or tokens**, in any file, including
   provenance notes and example commands. A download URL that carries a token is
   rewritten before it is recorded.
3. **Never commit a file whose redistribution status is unknown.** Not knowing
   the terms is a reason to leave it out, not a reason to guess.
4. **Git LFS is not in use.** Large binaries would need a decision record first.
5. **Extract only what the study area and analytical period need.** Do not
   download a national dataset and filter locally.
6. **Do not delete `raw/` to save space** while results derived from it are still
   being reported. If space forces it, record the checksums first so the same
   inputs can be re-obtained and verified.

## Current contents

Local-only samples retrieved during data discovery are listed, with their sizes
and checksums, in [`../docs/data-sources.md`](../docs/data-sources.md). That
document is the register; this one is the handling policy.
